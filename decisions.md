(2) **Extraction**. Java: the `package` declaration as a `module` symbol named by its dotted name; imports as written (`a.b.C`, `a.b.*`, static `a.b.C.member`); classes and records as `class`, interfaces and annotation types as `interface`, enums as `enum`; methods, constructors (`Type::Type`), and annotation elements as `method`; fields, interface constants, and enum constants as `const` (the store has no field kind; Go stored variables as `const` too). C#: namespaces (block and file-scoped) as `module` symbols by full dotted name (nested `Acme.Jobs.Internal`); `using` directives by the name they import (plain, `static`, alias, `global`); classes and records as `class`, structs and record structs as `struct`, interfaces as `interface`, enums as `enum`, delegates as `type`; methods and constructors as `method`; fields, constants, properties, and enum members as `const` (calls inside property accessors therefore belong to no method and are not recorded); verbatim `@name` stored as `name`. Both: nested types qualified through their outer types (`Outer::Inner::m`), the package or namespace never part of a qualified name, type parameters never part of a name (as Go drops a receiver's), one symbol per overload and per partial declaration, signatures from the first annotation or modifier to the body, capped at 1,024 bytes; a declaration whose text exceeds the cap drops its annotations or attributes and keeps its modifier keywords first, so a long annotation never hides `public` or `static` (review S4); a field declaration of several names gives each `modifiers type name`, the prefix cut once just past the bound before it is copied (review M1: 250,000 names behind a 500 KB annotation took 8.3 s and 8.0 s in a debug build before, 2.1 s and 2.0 s after; Go's multi-name `var` and `const` specs had the same shape and got the same cut, 9.6 s to 3.1 s, output unchanged). Not symbols: local and anonymous classes, lambdas, initializer blocks (Java), destructors, operators, conversion operators, indexers, events, local functions, top-level statements (C#), and anything inside a member body. Error-recovery nodes are walked through (complete declarations inside them are kept) and garbled names dropped. Visibility for module cards: a top-level type whose modifiers include `public`; package-private Java types and `internal` C# types are not public, and members are never listed (as for every language). Entry points: `package-info.java` and `Program.cs` by name, and any file with a `static` method named `main` (Java) or `Main` (C#); a top-level-statements file not named `Program.cs` is not one. Purpose line: the Javadoc block directly above `package` (the `package-info.java` convention), else directly above the first top-level type; the `///` summary (tags removed) above the first C# type; license blocks never. Test code: no file-name rule; Java and C# tests are test code through D99's directory rule (`test`, `tests`, `__tests__`, `testdata`), which covers the conventional `src/test` layout; `*Test.java` and C# `*.Tests` project directories are conventions, not language rules, so, as E17-34's review held for other languages, they do not count. The repository map lists a Java or C# file's types and members, not its package or namespace symbol. (3) **Calls**. Recorded: unqualified `m()` as plain, `this.m()`, `super.m()`, `base.m()` as self calls, `a.b.m()` on a chain of plain names as a path call (variable, field, type, or package-qualified type look alike), any other `expr.m()` as a receiver call, `new T(...)` as a plain call to `T` (it resolves to the type, as `new X()` does in script), a C# `using` alias in a qualifier rewritten to the last part of what it names; not recorded: method references, `this(...)`/`super(...)` constructor chaining, `nameof`, calls on predefined C# types (`string.Join`), bare names as arguments (no free functions), calls in field initializers, initializer blocks, and property accessors. Resolution (query time, never across languages): candidates are the same language's symbols of the name that the caller may reach: another file's `private` member never; a Java member without `public` only from its own package, a `protected` one also from a subclass; a C# member without an access modifier only from another declaration of its own (partial) type, and `internal`, `protected`, `public` from anywhere; an interface member without a modifier from anywhere, in both languages (it is public; review M2); test code only from test code.
