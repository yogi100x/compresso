| D80 | Staleness check trusts untouched files | Owner decision 2026-11-15, bounding the per-call cost of staleness checks (SEC-005). A tool call no longer hashes every indexed file. | D101 | One `compresso_grep` call carries several independent lookups: scoped patterns plus read ranges | Proposed 2026-11-20 by the implementing session; awaits owner confirmation. Finding: in session benchmarks (five runs per arm) cost followed round trips, because every message re-reads the context, not result size (result characters about equal across arms, ~110k): the exploration agent made 64 calls per run on a Go task (43 grep, 16 read) against 25-31 for arms that chain 3-4 independent lookups into one call, 43 against 25 on a TypeScript task, 49 against 31 on a Rust task; the E17-34 rule to send independent lookups together did not reduce messages, and every recorded message carried exactly one tool call. Decision: (1) a `compresso_grep` `patterns` entry may be `{pattern, path}`: that pattern searches only files admitted by both the call's `path` and its own scope, in the same scan (atlas `GrepOptions.scopes`), so fitting, repeats, and test naming still work across patterns; (2) `ranges`, the `compresso_read` multi-range argument with its gates, per-range errors, and text windows, reads lines of any files in the same call; (3) text result: one `# PATTERN [in SCOPE] — ...` section per pattern, the grep notes, then one `@@` section per range, so raw file content never precedes a grep header, and a grep file header path starting with `# ` or `@@ ` has its first character replaced by `?`; (4) bounds: with ranges and no `max_tokens` the default is the grep default plus the read default (2,000); `max_tokens` is split between patterns and reads in the proportion of those defaults (grep share at least 300), patterns share round-robin and ranges evenly, reads also get what the patterns left, every cut has a note, and both the text and the JSON form are held to `max_tokens` as sent (with ranges the grep share is at most half of a small budget; a JSON result whose envelope cannot fit fails with `invalid_arguments`); (5) a pattern whose own scope is invalid fails only its own section, and the call fails when every pattern does; (6) the full profile accepts (1) and (2) without advertising them, because installed clients run the full profile (D92) and the exploration agent file shows a packed call; full schemas, instructions, and goldens are byte-identical; (7) behaviour change in the lean schema: grep advertises both `patterns` shapes and `ranges` and no longer the single `pattern`; read advertises only `ranges` and `max_tokens`, no longer `path`, `start_line`, `end_line`, or `gate`; every one is still accepted. Token arithmetic (o200k / Anthropic-calibrated, against full 4,033 / 4,639): lean 2,010 / 2,313 before; adding the two `patterns` shapes, `ranges`, and the packing wording without removals measured 2,074 (over the half-of-full limit of 2,016); removing grep `pattern` and read `path`, `start_line`, `end_line` gave 2,008 / 2,310, removing read `gate` (which cannot be combined with `ranges`) and the final wording give 1,992 / 2,292, a margin of 24 / 27. A client that validates arguments against the advertised schema (`additionalProperties: false`) would refuse the unadvertised arguments; no Compresso doc, instruction, or agent rule tells a lean session to use them, and none of the 98 grep and 35 read calls in the live check used them. (8) The lean grep and read descriptions and the exploration agent steer to packed calls: one call carries every lookup you can already name, usually the next searches in `patterns` and the follow-up reads in `ranges`, with a worked example of one call with three lookups; `compresso_read` only when nothing is left to search, with every range in one call. `compresso_edit` already edits several files in one call, all or nothing (ADR-0035); unchanged. (9) Round trips found in live runs of the first cut: a rename scoped by `path` now also counts and lists whole matches of the old name in indexed files outside its scope, after every operation of the call (read gate only, the call's rename read budget, nothing written; files it could not search are listed as not searched and do not make it incomplete), and is not `complete` while any remain, because a live run stopped at "0 remaining" with one whole match outside the scope (ADR-0035 amended); the grep regex compiled-size bound rises from 256 KiB to 2 MiB per compiled program (the lazy-DFA caches stay 2 MiB, set explicitly; with a forward and a reverse program and two caches a pattern holds at most about 8 MiB, 64 MiB for 8; measured, 8 patterns at the limit over 2.4 MB of text added 22.7 MB peak resident memory; matching stays linear-time, so the bound is memory) because ordinary counted repetitions of Unicode classes such as `\D{0,30}` compile to about 1 MiB and were refused in two runs, and a larger pattern's error now says to shorten counted repetitions or use ASCII classes; in the lean profile a grep limit above its advertised maximum is clamped with a note instead of failing (below-minimum values and the full profile still fail; a lean `max_tokens` under 300 still fails). No shell, wrapper, hook, or process capability (D76). Live check of the first cut (orchestrator, held-out Go task, 3 runs, lean server with the agent file): 42/48/52 calls against a 63.8 mean, $0.462/$0.445/$0.506 against $0.547, 47-48 of 48 facts, 16 of 16 edits; 60 of 98 grep calls packed patterns (2.0 per call), `ranges` was never used and reads stayed at 11-12 separate calls per run, so the read wording was strengthened after it; the only tool error was a `max_matches_per_file` of 100 over the advertised maximum of 50, not an unadvertised argument. The final wording has not been measured live. Known gaps, measured: (a) `ranges` inside `compresso_grep` was used 0 times in about 180 grep calls over 6 live lean runs; reads went to `compresso_read` with 1-6 ranges per call, and patterns per grep call rose to 2.7-3.6; final binary (3 runs): $0.493/$0.395/$0.440 (mean $0.443 against $0.547), 43/32/42 calls (against 63.8), 48 of 48 facts and 16 of 16 edits in each. (b) With a full-profile server, which every installer writes (D92), the agent never sent the packed form (1 run: 0 of 32 grep calls used a scoped pattern or `ranges`, 0 tool errors) and cost $0.672 with 49 calls and 154k result characters, against $0.443, 39 calls, and ~95k for the same binary and agent file on a lean server; the agent's benchmarked cost applies only to a lean server. Whether `--explore-agent` should also write a lean server entry is an owner decision; D92 and the installer are unchanged. (c) Raw range content is not escaped and can imitate a grep section or another `@@` header; the reader relies on placement: every grep section comes before the first `@@` range header. Rejected: a new batch tool (another schema in the lean surface, and the agent already reaches for grep); grouping scoped patterns into separate scans (loses cross-pattern fitting and repeats); serving packed arguments only in the lean profile (the installed full server would reject the agent's example). | E17-36 |
| D99 | The compact text form names test-code and repeated grep matches by line, and the exploration agent batches independent lookups | Proposed 2026-11-19 by the implementing session and revised after review the same day; confirmed by the owner on 2026-11-19. Finding (three runs of the long benchmark task after E17-33, 25-33 messages, $0.52-$0.61 against $0.51 for a shell-only run): re-reading context on every message cost as much as new tokens, so messages matter as much as result size. Of 167k replayed grep characters, 20% were matches in test code whose answer facts also appeared in code rows, 16% context rows, 4% lines a second pattern of the same call repeated.
