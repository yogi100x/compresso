## Critical

**A1. Compression can emit provider-invalid conversations; fail-open never fires.** Only 4 node kinds are protected; `tool_response`/`assistant_response` are droppable. Dropping a `tool_result` paired with a `tool_use` → Anthropic 400s the request; mutating signed extended-thinking blocks fails signature verification. No `reasoning` NodeKind exists; none of the 8 safety checks models provider pairing/signature invariants; the engine reports success so D38 fallback doesn't trigger. Violates owner constraint 4 in the proxy path (E11) built to add value. Fix: add provider-conversation invariant checks (tool_use/tool_result pairing, thinking-block immutability), a `reasoning` NodeKind (protected), and conversation-aware protection defaults in the proxy adapter. (02 §1, 03 §2.5, E11-02)

**A2. Purchase flow can't reach the device.** No ticket implements `compresso account`, the local device-code login client, or the `CloudClient` that E10-08 consumes; keychain credentials are assumed into existence. Fix: new E10 ticket (local account/login client). (build §8.2, E10-03/05/07/08)

## High — architecture

**A3. `compresso_compress` can return empty output as success.** `from_text` builds a single unprotected node; `pack_budget` drops whole nodes; over-budget single node → `""` with all checks passing. Fix: text segmentation spec for the MCP text path + minimum-output safety check. (E5-04, 03 §2.3)

**A4. Dedup-stub orphaning.** `pack_budget` preferentially drops the large surviving referent over its cheap stubs; `refs_valid` only checks file:line refs. Fix: stub→referent edges + `refs_valid` extended to node references, or pack-stage stub/referent coupling. (03 §2.3/2.5)

**A5. Latency budget unrealistic as specced.** Pipeline implies ≥5 full-graph tokenizations; tiktoken on MiB-scale inputs costs seconds; `latency_ok` fails only after time is spent; lazy tokenizer init lands o200k BPE load inside the first call's 200 ms. CI gate uses small fixtures only. Fix: incremental/differential token accounting, eager tokenizer init at server start (within the 500 ms startup budget, measured), large-payload latency fixtures. (03 §2.4, E5-06, 06)

## Medium
